Featured · Agent infrastructure

pr-graph: a merge gate that knows which PRs it isn't allowed to finish.

Agents review a pull request, fix its blocking findings on the PR's own branch, and a fresh reviewer checks each fix. Then a Python gate, not the model, decides whether it merges. If it can't verify a PR, it holds it and says why.

34known-bad states it must refuseRun in CI on every PR, starting from a real incident: PR #74's HIGH finding, unmasked input posted to GitHub.
Holds on C1 / H1Any open CRITICAL or HIGH finding blocks the merge, as do hold, hands-off and needs-owner labels and any change to CI, agent or gate config, which always go to a human.
Pinned to the reviewed commitA review only counts for the exact head and base SHA it saw. The merge pins the reviewed head, so a push after review makes GitHub refuse it. The gate itself runs from a pinned commit.
Typed handoffsReviewer and fixer agents exchange JSON reports checked against schemas, with no shared chat history to drift.
Scorecard per runEvery run ends with what merged, what's held and what needs an owner, with one line of reasons each.
Claude Code and CodexBundled launchers for both. Other agents can plug in through the same adapter contract.
